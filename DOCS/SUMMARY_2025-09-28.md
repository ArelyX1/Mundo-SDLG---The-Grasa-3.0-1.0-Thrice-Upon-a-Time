### 3. Dual-Entry Layout Recipe
- Go PVM uses absolute offsets: `entry=0` (refine), `entry=5` (accumulate)
- Layout trick: prepend jump stubs at offsets 0 and 5 pointing to the real entry
```
pub @main:
    jump @1380    // trampoline
    fallthrough   // 1 byte each → offsets 2,3,4
    fallthrough
    fallthrough
@acc:
    jump @1380    // offset 5
    fallthrough
```
- Both entries 0 and 5 run the same body → validated with smoke guest

### 4. Wire Format Decision
| Call | Args Format | Guest Discrimination |
|------|-------------|---------------------|
| Refine | Single JSON `Item` (no trailing NUL) | `args.last() != 0` |
| Accumulate | Concatenated JSON `Op` reports + `0x00` | `args.last() == 0` |

### 5. PVM Args & Registers
- Args written at `0xFE000000` (ReadOnly); at entry: `R7`=base, `R8`=len
- VM reg numbering: r0=RA, r1=SP, r2=T0, r3=T1, r4=T2, r5=S0, r6=S1, r7=A0..r12=A5
- Halt: `mv a0, addr; mv a1, len; li ra, -65536; ret` (physical x10/x11/x1)

## Notes / Caveats
- **polkatool assemble** doesn't parse `mulhu` (from serde_json u128) → needs grammar patch in `polkavm-common/src/assembler.rs`
- `TestABIRoundTrip` hardcodes `entry=0` → must read `ENTRY` env for dual verification
- Amount encoding in report **must be RAW u128 string** (not decimal) to match native
- `raw_string` (u128→decimal) used only for nonce/fee — does not trigger mulhu
- GO PVM builds: `RUSTUP_TOOLCHAIN=stable` for polkavm; tests require `-count=1`
